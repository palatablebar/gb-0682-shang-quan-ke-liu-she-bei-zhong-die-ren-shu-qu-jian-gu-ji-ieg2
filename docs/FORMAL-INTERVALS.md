# 正式区间裁决：商场归属与分组

背景：共享采集平台接入两座商场，区域标签均只有 A、B、C。按标签合并会把两场人数塞进同一区间；按文件拆开会让同场的区域与交集各算一套。

裁决如下，七条均为强制不变量，由 `tests/test_mall.py` 逐项验证：

1. **正式区间身份 = (商场, UTC小时桶)**。商场归属取自记录级 `mall` 列；缺列或空值时取运行参数 `parameters.mall`；再缺省为 `default`。不以文件名为归属（同场的区域与交集可能分文件到达），不以区域标签为归属（A/B/C 两场复用）。
2. **估界页面与封存导出同一分组**。两者都读取 formal 正式区间存储，按 (商场, 时段) 排序分组；估界页不再临场重算正式区间，`/api/m5_calculate` 仍为复算预览接口。
3. **补传只重算受影响商场**。正式区间按商场独立晋升；本批未出现的商场保留原版本。补传文件须自含该商场的完整观测；某商场本批无可行区间时其正式版本保持不变。
4. **跨场交集不得进入正式区间**。`mall` 单元格含多场标记（如 `M1|M2`）的记录整行隔离，原因码 `CROSS_MALL`，作为证据保留在隔离区与封存导出中，但永不参与正式区间。
5. **同批重跑不新增版本**。批次按 run_id 幂等（INSERT OR IGNORE）；商场区间摘要（计算结果的 SHA-256）未变则该商场正式版本不变。
6. **切换失败页面仍用原版本**。批次入库与正式区间切换在同一事务，任一步失败整体回滚；估界页与封存导出继续读取原版本。
7. **原始观测不可覆盖**。runs.body 只插不改；复核仅更新 version/decision 列；补传产生新批次而非改写旧批次，任何批次的原始观测都可完整恢复。

实现位置：归属解析与跨场隔离 `app/modules/m2_mapping/rules.py`；分桶键 `app/modules/m3_versions/rules.py`；按 (商场,时段) 建模 `app/modules/m4_segments/rules.py`；区间携带商场 `app/modules/m5_calculate/rules.py`；正式存储与晋升 `app/store.py`（`_promote`/`formal_state`）；页面与导出同源 `app/web.py`、`app/main.py`、`app/modules/m7_archive/export_out.py`。
